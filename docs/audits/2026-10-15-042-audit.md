## Repeatable repository loop

```bash
uv sync --locked --no-default-groups --group dev
make audit
# .audit/core.json and .audit/core-logs/*.log
```

The 14 core checks cover the lock, lint, formatting, types, core tests, offline
doctor smoke, strict docs, release metadata, build, external wheel installation
and four behavioral examples. CI runs this same profile on Linux/macOS and Python
3.11–3.13 and uploads evidence even on failure. Reports/logs must be in a Git-ignored
directory or outside the repository. Missing tools, failures and timeouts are
recorded per check; later checks still run. Inspect individual logs for details.

```bash
uv sync --locked --no-default-groups --group dev --all-extras
# Install system FFmpeg and Tesseract first.
make audit-optional
# .audit/optional.json and .audit/optional-logs/*.log
```

Optional audit explicitly checks CPU-test prerequisites before running all
non-live tests; missing prerequisites fail its report. This command preserves the
existing environment. Thread bounds, Torch-backed Keras and offline Hugging Face
settings are enforced in child checks. Live Docker/service QA remains separately
available through `scripts/verify_services.py --wheel <path>`.

Reports include start/end commit, dirty state and content fingerprint (tracked
plus nonignored untracked source), per-check source states, selected commands,
logs and durations. An in-progress/interrupted report is unhealthy; unrun checks are explicit. Any source
change observed before/after a check permanently invalidates otherwise passing
checks, even if a later check restores the original tree. Edits restored entirely
inside one command cannot be detected by endpoint fingerprints; run release QA
on a stable CI checkout. Each check has a finite timeout (default 600 seconds); on timeout/interruption its process group
is terminated on the supported POSIX CI platforms. The CLI routes SIGINT, SIGTERM
and SIGHUP through cleanup, restoring previous signal handlers afterward. An
uncatchable SIGKILL or machine crash cannot run Python cleanup. The runner does
not install packages or silently repair source. Inspect the failure, add a failing regression,
fix it, and run the affected checks followed by the selected full profile again.

## Independent review and dispositions

The fresh read-only branch review covered `246bae9..07c8b36`. It found five
Important issues and no Critical/Minor issues. All entered one regression fix
pass: bounded ambient context variables (10,000 completed-scope probe), source
changes restored between checks, SIGTERM process-group cleanup/restored handlers,
invalid UTF-8 diagnostic reports, and ordinary/stepped/reversed/empty dataset
slices with isolated records. Eight new cases failed before the repairs; the
combined focused suite then passed 59 tests. Final full QA follows below in the
GitHub PR record; no second reviewer was used to substitute for these regressions.

The reviewer also set aside the following boundaries. These decisions retain
explicit limits rather than claiming unsupported behavior:

- Fingerprints cannot detect edits restored entirely within one command; detect
  and latch every observed boundary change. Cost if wrong: a transient edit can
  make local evidence incomplete; release QA uses a stable checkout.
- Secret values under arbitrary unrecognized keys require `mask_fields`;
  key-based masking is not a secret classifier. Cost if wrong: an unlisted secret
  could appear in inspection output.
- Wrong-type sampling arguments such as string fractions are outside the typed
  numeric API. Cost if wrong: untyped callers receive Python type errors instead
  of a structured validation error.
- `AIRE_CONFIG` selection remains unsupported; use an explicit configuration path
  or documented discovery. Cost if wrong: a caller expecting that undocumented
  environment variable may load defaults instead.
- Hosted-provider availability and production load remain unverified by local
  review; verify actual publication separately through the planned workflow and
  public-byte/install checks. Cost if wrong: an untested hosted/load scenario may
  fail; a release is never inferred from source metadata.
